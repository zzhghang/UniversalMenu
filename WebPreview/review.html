先绑定设置，再初始化条目

String 系列首次初始化现在读取已绑定的设置；分辨率条目也执行父类初始化。

原触发
已有设置值与资产默认值不同时，首次构建 String / Bool / Integer 条目，UI 当前值可能停留在默认值。
原原因
AddChildListData() 会立即初始化，而旧 Registry 在它之后才绑定 getter / setter；分辨率子类还跳过了父类初始化。

验证

P1FACTORY · 配置被代码覆盖02

“默认 0”变成 3，选项也会被替换

质量项与窗口模式由 BindingKey 特判，资产不是完整的事实来源。

触发
Integer 质量项配置 DefaultIntValue = 0，工厂会改为 3；修改质量选项或窗口模式默认值也会被固定分支绕过。
原因
名称包含 Quality / Scalability 就进入硬编码分支；0 被同时用于“合法值”和“未配置”。
修复
用显式 OptionSource 区分静态选项与动态提供器；使用 bHasDefaultValue 标识默认值存在性，保留合法的 0。
查看代码依据 +

MenuConfigData.cpp:14–17, 73–103, 122–150

return S.Contains(TEXT("Quality"))
    || S.Contains(TEXT("Scalability"));

const int32 DefaultVal =
    Data->DefaultIntValue != 0
        ? Data->DefaultIntValue : 3;

窗口模式分支固定三项并选择 WindowedFullscreen。可保留引擎动态提供器，但必须让编辑器明确显示哪些字段生效。

P2SHARED CONFIG · 顺序契约缺失03

用 TMap 定义有序的 UI 选项

地图、人数和普通下拉项的排列直接取决于 Map 迭代顺序。

触发
增加、删除、重建选项后，期望的 2 → 4 → 8 → 16 或地图顺序没有稳定的配置契约。
原因
AvailableOptions 与 AvailableIntegerOptions 都是 TMap，工厂直接遍历并追加到显示数组。
修复
改为 TArray<FMenuOption>，元素包含稳定 Value 和本地化 Label，以数组顺序显示，同时校验 Value 唯一。
查看代码依据 +

这是容器选择与 UI 顺序的契约问题，并不表示每次运行都会随机重排。TMap 仍适合按 ID 查询。

P2REGISTRIES · 同字段不同语义04

EditDependencyIds 混合了刷新与禁用

拆为 RefreshDependencies 与 EditConditions。条件包含 TargetId、比较符、期望值和禁用原因，明确 All / Any 组合。

P2MULTIPLAYER · 结构扩展风险05

Session 列表缺少明确的目标容器

表头配置改变了树结构，搜索结果却依赖固定的 Collection 层级。

触发
给 JoinGame 的类别填入 HeaderColumns 后，它不再生成 Collection，动态 Session 无处插入；若加多个 Collection，则每个都会收到同一批结果。
原因
建树逻辑把带表头的条目直接挂到 Tab；刷新逻辑却向 JoinGame 下所有 Collection 添加 Sessions。
修复
使用显式 SessionList 内容类型或 SessionContainerId，稳定保留容器；表头只影响显示，不改变树结构。

P1AUTHORING · 缺少配置防护06

错误配置只能在运行时暴露

触发
在 Options 的 Tabs / Categories 中新增一个未赋值元素，构建时直接解引用；重复 DataId 会覆盖查找表，未知绑定返回空指针后被跳过。
